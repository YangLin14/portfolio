URKL T800 Multi-Motion Tracking

Triton Droids entered URKL (Ultimate Robot Knock-out Legend), EngineAI's humanoid combat league where every team uses the same T800 humanoid. Our team passed the initial challenge round. The project stopped before the physical stage in China. I built the training infrastructure for chaining combat skills inside a single tracking policy in mjlab.

What I built

1. MultiMotionCommand

  • 🧩 Loads several named reference clips (kick, dodge, punch) and steps through a user-scripted sequence inside one policy's training
  • 🔁 The original single-motion path is unchanged

2. Closest-entry transitions

  • 🎯 When one clip ends, the command searches the next clip for the frame closest to the current state instead of restarting at frame 0
  • 🧪 The policy therefore trains on realistic transitions

3. Train, play, and runner support

  • ⚙️ Multi-motion configs wired through the train, play, and runner scripts
  • ✅ 23 passing tests

4. BVH-to-training data path

  • 🔧 Fixed the Holosoma retargeting setup (BVH unit scale, initial-pose selection, dependencies)
  • 📦 Converted retargeted qpos into 50 fps mjlab tracking files for kick, dodge, and warmup motions

5. GPU training runbooks

  • 📘 Runbooks so teammates could train on Colab A100 and the UCSD SDSC cluster

Status and limits

The pipeline initializes and parses end to end. A trained multi-skill policy is the next step. The sequence is scripted by the user; the robot does not choose skills itself. Closest-entry selection improves the reference but does not guarantee a physically stable transition; that has to come from training.

Credit

Original Kimodo BVH-to-T800 retargeting support was written by a teammate. Retargeting builds on Holosoma (Amazon FAR), and the training stack is mjlab.
